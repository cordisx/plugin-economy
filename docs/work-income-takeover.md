# Canonical work income and original Pet handover

The economic plugin owns work issuance, durable eligible-token frontier, fractional remainder, balance and append-only income ledger. Host `ctx.workSettlement` privately reads classified `usage/v2` root work and signs `cordisx.local-work-settlement/v1`. Callers supply only the pinned local income binding; they cannot supply amounts, snapshots, cursors, account IDs, baseline or lease policy. HTTP v4 remains compatible with its original financial continuity policy.

A first settlement for a pristine canonical account runs an IMMEDIATE transaction. It verifies original user identity, zero financial history and all work/history records, absence of configured finite reward sponsors, and absence of any previous income binding or receipt for this scope anywhere in the authoritative Store. It permanently claims one scope for the original account and closes new `pet-work:` grants for that account, independent of source alias. It then credits the current epoch's already Host-admitted prefix with `floor(eligibleTokens / 10000)` and persists the fractional remainder, exact first observation, takeover receipt and ordinary work-income ledger entry together. It never guesses raw pre-ledger history. A configured sponsor could hold an unsubmitted original owner intent, so its presence requires original-owner reconciliation rather than pristine inference.

Current-profile issuer custody evidence is required before actual adoption: the dedicated trusted issuer and its target must cover the actual work scope/epoch from enabledAt; current-profile other registered income targets and prior signed payments must be reconciled. Host must also atomically claim persistent private profile-wide scope custody before any work payment transport. This custody binds the original target realm, instance and canonical account, rather than a source alias, and survives owner disposal, process replacement and unknown replies. Legacy HTTP-v3/v4 attempts must reserve their leased policy before transport too; incompatible existing target or policy requires reconciliation. A started custody record with missing persistent data fails closed. A single realm's empty ledger alone does not establish machine-wide absence. The current deployment evidence is scoped to the verified original profile, sole canonical realm and observed epoch. Other profiles, undiscovered sources and unobserved historical work are not silently treated as unpaid or never enabled.

Durable receipt identity is the hash of binding, classified cursor and policy, independent of whether the first frontier has committed. Exact first-snapshot retries, concurrent calls and unknown-response recovery return the same stored receipt and event. Same-epoch monotonic admitted differences settle using the saved server cursor and remainder after reconnect or process replacement. A different ledger epoch provides no comparable old difference; it establishes an anchor and retains previously accumulated fractional tokens. Regressions, conflicting counters, retired epochs and alternative accounts/scopes fail closed. Old HTTP-v4 advances are rejected once this account has selected durable policy. Legacy-sponsored work that committed first prevents pristine takeover; takeover that committed first rejects new old-Pet work grants. Existing matching receipts remain recoverable without new transfer. Unrelated finite sponsor agreements retain their original conserved policy.

Original Pet has permanently disabled its new work producer. Its owner-only `petWorkRetirement.exportHistory()` reads `pet-system` and `pet-work-rewards-v2` twice, verifies stable original revisions and values, and exports economic projections and original JSON snapshot hashes without initialization, writes or grants. It preserves missing, unavailable, invalid and pending records as distinct facts. This unsigned owner audit export is not a server-authorized mint proof. Shared-wallet sponsor income is already money in the ledger and must never be minted again. Internal old Pet balance requires an original snapshot and existing operator-approved migration entitlement; old sponsored pending work reuses the exact original source/event/amount. Historical receipts, cursors and remainders require original-owner custody verification and full server receipt reconciliation before import.

Balance readiness, durable current-scope income acceptance and complete legacy-history reconciliation are separate statuses. The original `requires-retirement` declaration and unset correction are preserved during current-scope first takeover; no fabricated never-enabled declaration or new wallet is created.
