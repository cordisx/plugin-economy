# Audited correction of one erroneous empty work scope

This is an explicit operator recovery for the verified configuration-directory continuity incident. It is never a general migration, sponsor grant, balance adjustment or a caller-selected scope. Host must prove that the original usage ledger and epoch remain intact, pin the original canonical development configuration root, and admit its existing classified snapshot through the normal private work settlement service. Both incorrect and original Host custody records remain durable; no cache, ledger or custody record is deleted, renamed or copied.

The normal operator command is `npm run admin -- prepare-empty-scope-correction INSTANCE PLAN_JSON`, with the original `ECONOMY_DB`. The exact JSON plan contains only contract `economy.empty-work-scope-correction/v1`, instanceId, original accountId, fromScopeId, toScopeId, expectedEventId and evidenceDigest. The digest identifies the independently reviewed root-cause, original-ledger continuity and current-epoch sole-issuer/unpaid evidence. There is no amount, snapshot, baseline, cursor, entitlement or account reassignment field. Sole must prepare this exact reviewed plan; a plugin/user bearer cannot authorize it.

Preparation runs an IMMEDIATE transaction and requires exactly one existing durable first observation and receipt with revision0/tokens0/amount0/remainder0, matching takeover baseline and original account, zero wallet, no money/order/reservation/grant/history/lease records, and no finite reward sponsor. Correct scope must have no binding, takeover or prior receipt anywhere in the authoritative Store. It stores the complete original rows and their digest with the authorization and permanently retires the incorrect scope. Preparation does not change the current wallet, active frontier, receipt, observation or balance. Matching retries return the existing authorization and cannot change its target.

The next normal Host private settlement for the authorized correct scope rechecks the original delegation and every exact zero row under the final IMMEDIATE financial transaction lock. It checks the correct scope is still unpaid/unclaimed and the source matches the original classified source. It atomically corrects the current account's scope claim, credits only the execution-time Host-admitted prefix, saves remainder/frontier/receipt/observation and marks the correction completed. The incorrect zero receipt and observation remain unchanged, its original takeover/frontier are retained in the audit, and the retired-scope fence prevents all new work through that scope in any realm or policy. Exact stored zero receipt recovery is readonly. The account itself is never rebound or replaced.

Any new relevant state, nonzero token/remainder/amount, extra record, different source, foreign target or changed audited row causes rejection. Failed receipt insertion rolls back activation and money together, leaving the prepared authorization and original empty frontier intact. Concurrent or unknown-reply retries use the normal stable settlement event and cannot duplicate credit. Unobserved raw history is not inferred or paid.

The Wallet observer only changes its issuance-document scope after reading the original account's prepared/completed server correction and matching the exact old receipt event. It saves the complete previous document value in scopeHistory using normal owner CAS and preserves the original economy-local-wallet-v1 document. Server authorization and signed actual Host usage remain the sole accounting authority; the document audit is not a mint proof.
